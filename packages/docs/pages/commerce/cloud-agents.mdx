# Set up a cloud store with an AI agent

elisym Cloud runs a Pay Core store for a merchant: the node, its keys, its RPCs and its relays are ours to keep running, and the merchant pastes a Buy button into their page. This page is a runbook for an AI agent that sets such a store up through the cloud API, top to bottom. Every step is a request the agent can make itself, except two the merchant does by hand: paying for the plan and, optionally, proving payout addresses with their wallet.

Run it with a coding agent that can run TypeScript (Node.js 22 or newer, or Bun). The merchant can do the same in the console at [cloud.elisym.network](https://cloud.elisym.network); both sign in with the same owner key.

```ts
// The constants every step below uses.
const API = 'https://api.cloud.elisym.network';
const TERMS_URL = 'https://cloud.elisym.network/terms';
```

## 1. Make the owner key

The owner key is the merchant's sign-in: one key is one store, and whoever holds it controls the store. Make it once, save it to a file only the merchant can read, and give the merchant that file (the console signs in with it).

```bash
npm install nostr-tools@~2.23.0 @elisym/commerce@~0.13.0
```

Run this once, as a script of its own:

```ts
import { writeFileSync } from 'node:fs';
import { nsecEncode } from 'nostr-tools/nip19';
import { generateSecretKey } from 'nostr-tools/pure';

const secretKey = generateSecretKey();
writeFileSync('owner-key.txt', `${nsecEncode(secretKey)}\n`, { mode: 0o600 });
```

Never print the key, and never send it anywhere but this file. A lost key is a lost store.

## 2. Sign each request

Every request but `GET /tiers` carries a Nostr HTTP auth event (kind 27235) in its `Authorization` header. The server checks that the event:

- names the exact URL in a `u` tag (origin and path, as sent) and the uppercase method in a `method` tag;
- carries a `payload` tag with the lowercase hex sha256 of the exact body bytes sent (a request with a body must have one);
- is dated within 60 seconds of the server's clock, and was not used before (a random `nonce` tag keeps two equal requests in one second apart);
- fits the header: `Nostr ` followed by the base64 of the event's JSON, at most 8,192 characters.

The steps from here on are one script: this block holds every import the later blocks use.

```ts
import { createHash, randomBytes } from 'node:crypto';
import { readFileSync } from 'node:fs';
import { buildPaytoEvent, buildStoreAuthEvent, encodeProductNaddr } from '@elisym/commerce';
import { decode } from 'nostr-tools/nip19';
import { finalizeEvent, getPublicKey } from 'nostr-tools/pure';

const decoded = decode(readFileSync('owner-key.txt', 'utf8').trim());
if (decoded.type !== 'nsec') {
  throw new Error('owner-key.txt holds no nsec');
}
const ownerKey = decoded.data;

/** The server's clock minus ours, from the Date header of the last answer. */
let clockOffset = 0;

function readClock(response: Response) {
  const date = response.headers.get('date');
  if (date !== null) {
    clockOffset = Math.round((Date.parse(date) - Date.now()) / 1000);
  }
}

/** The plans; also sets the clock offset (call it first, and again after a `stale`). */
async function readTiers() {
  const response = await fetch(`${API}/tiers`);
  readClock(response);
  return (await response.json()).tiers;
}

async function call(method: 'GET' | 'POST', path: string, body?: unknown) {
  const url = `${API}${path}`;
  const bytes = body === undefined ? undefined : new TextEncoder().encode(JSON.stringify(body));
  const tags = [
    ['u', url],
    ['method', method],
    ['nonce', randomBytes(16).toString('hex')],
  ];
  if (bytes !== undefined) {
    tags.push(['payload', createHash('sha256').update(bytes).digest('hex')]);
  }
  const event = finalizeEvent(
    {
      kind: 27235,
      created_at: Math.floor(Date.now() / 1000) + clockOffset,
      tags,
      content: '',
    },
    ownerKey,
  );
  const response = await fetch(url, {
    method,
    headers: {
      authorization: `Nostr ${Buffer.from(JSON.stringify(event)).toString('base64')}`,
      ...(bytes === undefined ? {} : { 'content-type': 'application/json' }),
    },
    ...(bytes === undefined ? {} : { body: bytes }),
  });
  readClock(response);
  const answer: any = await response.json();
  if (!response.ok) {
    throw new Error(`${method} ${path}: ${response.status} ${answer.error} ${answer.detail ?? ''}`);
  }
  return answer;
}
```

An error answer is `{ "error": "<code>", "detail": "..." }`; [Errors](#errors) says what to do with each code. When a request is refused as `stale`, call `readTiers()` once and send it again.

## 3. Pick a plan and agree to the terms

```ts
const tiers = await readTiers();
const { tenantId: existing, termsVersion } = await call('GET', '/owner');
```

`existing` is not null when this key already has a store: go on with that id and skip the signup. Otherwise show the merchant the plans that are `selfServe`, each with its `name`, `price` and `display` limits, and let them pick one.

Show the merchant the terms at `TERMS_URL` and ask them to agree. **Call `POST /signup` only after the merchant says they agree to the terms.**

```ts
const tenantId: string =
  existing ??
  (
    await call('POST', '/signup', {
      tier: 'starter', // the id of the plan the merchant picked
      terms: termsVersion,
    })
  ).tenantId;
```

The store is on mainnet: its buyers pay real stablecoins.

## 4. Have the merchant pay

```ts
const { url } = await call('POST', `/tenants/${tenantId}/checkout`);
```

Give the merchant `url`: it opens the card payment. To pay in crypto instead, the merchant signs into the console with the key file and pays in its Pay step. Then poll the status every 5 seconds until the payment is in and the store key is made:

```ts
async function status() {
  return call('GET', `/tenants/${tenantId}/status`);
}

let current = await status();
while (current.gates.activation === 'not_paid' || current.storePubkey === null) {
  await new Promise((resolve) => setTimeout(resolve, 5000));
  current = await status();
}
```

## 5. Name the store and turn its rails on

Ask the merchant for the store's name and the wallets they want to be paid to: a Solana wallet for USDC on Solana, a Tempo wallet, and a wallet for USDC on Ethereum, Arbitrum or Base. **A Solana or a Tempo wallet is required**: the checkout offers Ethereum, Arbitrum and Base only next to one of them. A rail is on only when the store has a payout on it, so send exactly the rails of the wallets given:

```ts
await call('POST', `/tenants/${tenantId}/store`, {
  name: 'My store',
  solana: {}, // { } is the cloud's RPC; leave a rail out to keep it off
  evm: { base: {} },
});
```

To change it later, send the `choice` of `GET /tenants/:id/store` with your change: the store body is the whole choice, never a patch. Then [wait for the save](#waiting-for-a-save) until `kept.rails` names every rail you turned on (`solana`, `tempo`, `ethereum`, `arbitrum`, `base`).

## 6. Sign the payouts

The payout list (who gets paid, per coin) and the store authorization are two Nostr events the owner key signs. Build them with `@elisym/commerce`:

```ts
const createdAt = Math.floor(Date.now() / 1000) + clockOffset;
const payoutList = finalizeEvent(
  buildPaytoEvent({
    ownerPubkey: getPublicKey(ownerKey),
    accept: [
      {
        caip19:
          'solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp/token:EPjFWdd5AufqSSqeM2qN1xzybapC8G4wEGGkZwyTDt1v',
        address: '<the Solana wallet>',
      },
      {
        caip19: 'eip155:8453/erc20:0x833589fcd6edb6e08f4c7c32d4f71b54bda02913',
        address: '<the Base wallet, as the merchant gave it>',
      },
    ],
    createdAt,
  }),
  ownerKey,
);
const auth = finalizeEvent(
  buildStoreAuthEvent({
    storePubkey: current.storePubkey,
    mode: 'hosted',
    operator: new URL(API).hostname,
    createdAt,
  }),
  ownerKey,
);
await call('POST', `/tenants/${tenantId}/owner-events`, { payoutList, auth });
```

- Use only `accept` entries, one per coin, each on a rail the store has on. List a Solana or Tempo payout first, before any on Ethereum, Arbitrum or Base. The coins: USDC on Solana as above; on Tempo `eip155:4217/erc20:0x20c000000000000000000000b9537d11c60e8b50` (USDC.e) and `eip155:4217/erc20:0x20c0000000000000000000000000000000000000` (pathUSD); USDC on Ethereum `eip155:1/erc20:0xa0b86991c6218b36c1d19d4a2e9eb0ce3606eb48`, Arbitrum `eip155:42161/erc20:0xaf88d065e77c8cc2239327c5edb3a432268e5831` and Base `eip155:8453/erc20:0x833589fcd6edb6e08f4c7c32d4f71b54bda02913`.
- An EVM address is checked against its EIP-55 checksum when it has mixed case: pass it exactly as the merchant gave it.
- The authorization is in `hosted` mode with no expiry, naming the API's hostname as the operator.
- A new list must be dated after the one the store keeps. Re-sign the whole list for any change.

Then [wait for the save](#waiting-for-a-save) until `kept.payoutList.id` is `payoutList.id`. These payouts are not verified: the merchant can prove each address with their wallet in the console, and the checkout then marks it verified.

## 7. Add the products

Each product is a `PRODUCT.md` text under a name of lowercase letters, digits and dashes (at most 63, starting with a letter or digit). The name is the product's id: it never changes once published.

```ts
const products = {
  'deposit-10': '---\ntitle: Deposit 10 USD\npriceUsd: "10"\n---\n\nAdds 10 USD to your account.\n',
};
await call('POST', `/tenants/${tenantId}/products`, { products });
```

- `priceUsd` is quoted: a bare number is refused. The buyer pays it 1:1 in a stablecoin.
- The body is the whole set: a product left out is not deleted (a published product never is), so to stop selling one, send it with `onSale: false` in its front matter.
- One product is at most 4,096 bytes, measured as its text written as a JSON string (escapes count). The plan caps how many products a store has (`limits.products` of its tier).

Then [wait for the save](#waiting-for-a-save) until `kept.productsDigest` is the digest of the set you sent:

```ts
/** sha256 of the set as JSON with its names sorted as strings (never via an object: "10" sorts before "2"). */
function productsDigest(set: Record<string, string>): string {
  const entries = Object.entries(set).sort(([left], [right]) =>
    left < right ? -1 : left > right ? 1 : 0,
  );
  const json = `{${entries.map(([name, text]) => `${JSON.stringify(name)}:${JSON.stringify(text)}`).join(',')}}`;
  return createHash('sha256').update(json, 'utf8').digest('hex');
}
```

## Waiting for a save

Each save above answers at once with a `cycleId`; the store applies it a moment later. Follow the state, never the cycle id (a retried save continues under a new id). Poll `GET /tenants/:id/status` every 5 seconds:

- **Applied** when the kept state shows the change (as each step says), whatever `pending` says.
- **Refused** when `pending` is false and the change is not applied. `lastProblems.store`, `lastProblems['owner-events']` or `lastProblems.products` then lists what to fix: fix it and send again. When the list is null, the failure was ours and we were alerted: wait and check again later.
- While `pending` is true, keep polling: a save that takes long is being retried. After 10 minutes, tell the merchant to open the console: we were alerted.

## 8. Launch

Poll the status until every launch gate is green: `gates.activation` is null, `gates.homeReady`, `gates.storeSetUp` and `gates.noCyclePending` are true. Then launch:

```ts
await call('POST', `/tenants/${tenantId}/launch`);
```

Poll the status until `runState` is `live`. When it is `needs_resign`, sign the payouts again (step 6). When it is `could_not_start`, tell the merchant to open the console: we were alerted. `applying` and `starting` mean wait.

## 9. Install the Buy button

```ts
const store = await call('GET', `/tenants/${tenantId}/store`);
const names = store.productNames ?? Object.keys(store.products);
```

Put one button per product in the merchant's page, each naming its `naddr`:

```ts
const tag = store.loader === null ? 'elisym-buy' : 'pay-buy';
const buttons = names.map((name: string) => {
  const naddr = encodeProductNaddr({ storePubkey: store.storePubkey, d: name }, store.relayHints);
  return `<${tag} product="${naddr}" network="mainnet"></${tag}>`;
});
```

and the loader script once. When `store.loader` is null, it is this one:

```html
<script
  src="https://pay.elisym.network/v3/embed.js"
  integrity="sha384-FPsJfAuhwQU0mlPKTKLwCTp1YGK6aFRh0pT+Gl1T3UML2jlIK7EkW8FW5ue2qFJX"
  crossorigin="anonymous"
></script>
```

Otherwise the store sells through a partner: use the same script with `store.loader.src` and `store.loader.integrity` in place of `src` and `integrity`.

[The widget](/commerce/widget) has the button's options (`theme`, `label`, `display`, `collect-email`). When you are done, tell the merchant where the key file is, that it signs them into the console, and how to make a small test purchase.

## Errors

| Code | What to do |
| --- | --- |
| `missing`, `malformed`, `bad_signature`, `wrong_kind`, `wrong_url`, `wrong_method`, `wrong_payload` | The auth event is built wrong: check step 2 (the `u` tag is the exact URL, the payload hashes the exact bytes sent). |
| `stale` | The clock is off: call `readTiers()` to read the server's `Date`, then send again. |
| `replayed` | The same auth event was sent twice: sign a new one. |
| `forbidden` | The key is not this store's owner (or is a partner or operator key), or the signup lapsed unpaid: `GET /owner` then answers a null `tenantId`, and the merchant signs up again. |
| `terms_not_accepted` | The terms version changed: read `GET /owner` again and ask the merchant to agree again. |
| `key_owns_a_store` | This key already has a store: `GET /owner` names it. |
| `bad_tier`, `bad_network` | Use a `selfServe` id from `GET /tiers`, and `mainnet` or `devnet`. |
| `rate_limited` | Too many stores signed up from this address: wait up to an hour. |
| `card_subscription_live`, `card_from` | The plan is paid already: go on polling the status (step 4). |
| `payment_window_closed`, `owner_unconfirmed` | The signup can no longer be paid by card: ask the merchant to contact us. |
| `tenant_gone` | The store was handed over or destroyed: stop, and tell the merchant. |
| `no_card_for_tier`, `card_not_set_up`, `stripe_unavailable`, `stripe_refused` | Card payment is not available now: the merchant pays in crypto in the console. |
| `no_store_key` | The store key is not made yet: wait for `storePubkey` in the status. |
| `store_first` | Save the store (step 5) before the payouts. |
| `store_refused` | `detail` lists what to fix, one problem per line. |
| `not_on_plan` | The plan does not take your own RPC: send `{}` for the rail. |
| `over_limit` | More products than the plan takes: `detail` says the limit. |
| `already_activated` | The store is launched already. |
| `operator_activates` | We launch this store with the merchant: nothing to do. |
| `not_paid` | Wait for the payment (step 4). |
| `held`, `owner_mismatch`, `not_redeemed` | Ask the merchant to contact us. |
| `cycle_pending` | A save is still applying: wait for `gates.noCyclePending`, then launch again. |
| `home_not_ready`, `store_not_set_up` | Wait for `gates.homeReady`, or finish steps 5 to 7. |
| `domain_check` | The store has a domain whose record does not name it yet: the merchant fixes it in the console. |
| `bad_body`, `not_found` | The request is built wrong (its body is not JSON, or the path is not a route): check it against this page. |
| `internal` | Something failed on our side: wait a minute and send it again. |
