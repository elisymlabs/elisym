# Askr: a shopping assistant for your site

Askr puts a chat assistant on your store's site. It answers visitors from your own catalog and policies, shows product cards with prices taken from the catalog (never from the model), and hands off to the product page or your cart. It sells nothing itself and takes no payments.

Your catalog, policies and the assistant's settings live on Nostr, signed by keys you control. The Askr server runs the assistant: it reads what you published, answers visitors, and keeps the budget your plan allows.

## The keys

| Key                  | Who holds it                                                                      | What it signs                                                             |
| -------------------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| Owner key            | You. It is the store's identity: the embed snippet names its npub.                | The store config and which catalog keys may write your products.          |
| Catalog key (server) | The Askr server, one per store.                                                   | Products and policies you edit in the admin, or that a connector imports. |
| Catalog key (yours)  | Your backend, CI or agent ([Catalog from an agent](/askr/catalog-from-an-agent)). | Products and policies you publish yourself.                               |
| Assistant key        | The Askr server, one per store.                                                   | The assistant's replies.                                                  |

A catalog key writes products only once the owner key authorizes it. The owner can revoke it at any time in the admin, and a leaked catalog key never touches payments: listings it signs can never carry payment terms.

## Product sources

A store reads its products from exactly one source, chosen in the admin:

- **Admin**: import a CSV or edit products in the admin, attributes, sizes, colors and other variants included. They are signed by the server's catalog key. In a CSV file, a column such as `attr:Material` is an attribute and `option:Size` an option; each variant is one row with the same `d`, with optional `variant_id`, `variant_price` and `variant_available` columns, and `*` in an option cell means any value of that option. The admin offers an example file.
- **Your catalog key**: publish from your own code with the SDK, or from an agent with the MCP tools.
- **Connector**: Shopify, WooCommerce or a Google product feed, imported on a schedule. Only public endpoints are read: no store token is needed. A shop behind a bot check (such as Cloudflare's) that refuses automated readers cannot be read; let the `AskrConnector` user agent through, or use a CSV file or a feed. Shopify tags that are the shop's own bookkeeping (`key: value` and the like) are not imported as topics. Shopify and WooCommerce also get native add-to-cart on the shop's own site.
- **Pay Core**: an existing [Pay Core](/commerce/quickstart) store's listings, read as they are. Give each product a `url` on one of the store's origins or link origins, so its card links to the product page.

## Onboarding

1. Open the admin at `https://api.askr.elisym.network/admin/` and let it make a secret key for your store, or paste the one you have (an `nsec`). Save it: it is your store. The admin never stores it; it stays in the tab's memory until you sign out.
2. Create the store. Fill in its name, language, currency, the origins your site runs on, the product source, and the assistant's voice and instructions. One signing step stores the config and the catalog key authorization.
3. The store stays pending until it is activated on a plan. Meanwhile the admin shows your settings from what you signed, which the server holds; your browser checks every signature, as it does for the relay. Once active, the server publishes what you signed, the relay becomes the source, and the assistant starts answering.
4. [Embed the widget](/askr/embed) on your site.

From the admin you can later edit the settings, import products, edit policies, set up a connector, and see usage against your plan; under Advanced, manage catalog keys, rotate the assistant key, and replace your secret key.

The overview counts **conversations**: a conversation is one visitor's chat, up to 24 hours from their first message, that got at least one answer. Each is counted once, on its first answer, however many questions follow or however often a turn is retried; a chat whose questions all failed is not counted. The count starts around the server upgrade that introduced it: chats still open then are included, older ones are not. A server operator should not run instances of the old and new version side by side during that upgrade, since an old instance answers without counting. Next to it are the open conversations (chats started in the last 24 hours) and the advisory product link clicks.

## Replacing a lost or leaked secret key

Lost your secret key, or think someone else has it? Choose **Lost your secret key?** on the sign-in page (or **Replace my secret key** under Advanced):

1. Enter your Store ID: the `npub1...` in the chat code on your site. The admin first checks that nothing stands in the way.
2. The admin makes a new secret key. Save it. If you come back later, tick "I already made and saved a new secret key" and paste it, instead of making another.
3. Prove the store is yours: add `<meta name="askr-verification" content="npub1...">` (your new Store ID) to your home page, or a file at `/.well-known/askr` with the new Store ID on a line of its own, on a site the store lists. Keep it there: a connector to your shop checks it too.
4. The server checks the site and moves the store to the new key. The admin then shows the settings the old key signed last: check them (if someone else had the old key, they may have changed them), and sign them with the new key.

Products, policies, the connector, your plan and usage stay as they were. The old key stops working for good. The chat on your site is unavailable until you have signed your settings with the new key; then the chat code on your site works again, as a widget embedded with the old Store ID follows the store to the new one. Still, replace it with the new code from the Embed tab, which no longer depends on the old key. Chats that were open start afresh. Catalog keys you authorized for your own backend or an agent are not carried over: authorize them again under Advanced (for an elisym agent, run `askr-key` again with `--store <new Store ID> --rotate`).

A site counts once the store has listed it for 72 hours, while the store is active and its settings list it, and for 30 days after that: someone holding a stolen key cannot add a site of their own and take the store at once, nor lock you out by removing yours. The sites the store has had longest are checked first, so sites added later never crowd yours out. Sites on shared hosting where anyone can claim a name (such as `vercel.app`, `netlify.app` or `github.io` subdomains) never count. If someone moved your store away, start again from your original Store ID: the store is found wherever it moved. A store whose products come from a Pay Core store needs our help afterwards to link Pay Core to the new key.
