# Set up with an AI agent

Paste one prompt into an AI coding agent that has a terminal (Claude Code, Cursor and the like) and it sets up Askr for you without opening the admin: it reads your site, asks you a short list of questions once, creates the store, publishes your products and policies, adds the chat to your site and checks that it answers.

## What it does

The agent runs the Askr commands of the elisym CLI, one step each, and reads their JSON output:

1. it looks at your site and at `askr status`, then asks you everything once, with a proposed answer for each question;
2. it creates the store and signs its settings (`askr init`), publishes products (`askr products` from a file, or `askr connector` for a shop) and policies (`askr policy`);
3. it inserts the widget snippet into your site's shared layout (`askr embed`), or tells you exactly where to paste it, and puts the store's `llms.txt` at your site's root for AI agents ([AI agents and your store](/askr/ai-agents));
4. it checks that the chat is served (`askr status --probe`) and ends with a summary: your Store ID, where your secret key file is, the admin as the fallback, how to upgrade and how to update products later.

You need an agent that can run commands, and Node 22 or newer.

**The plan.** The agent asks whether you want Free or a paid plan, and never answers for you. Free: it runs `askr plan free` on your word and the store goes live at once, within Free's limits. Starter, Growth, Pro or Scale: it runs `askr plan <plan>` (with `--yearly` for yearly billing) and gives you the checkout link it prints; you open it and pay (Stripe Checkout, prices include tax), and the store goes live once the payment goes through. The agent never opens the link or pays for you. Until then the store stays pending: the setup ends with the product file and policy drafts written (in `~/askr-setup/`) and the widget added to your site (it stays hidden until the store is active), and the summary lists the commands to run once the store is active. Enterprise is set up by us: message us with your Store ID.

## The prompt

Copy it into your agent as it is:

```text

Run every command as `npx -y @elisym/cli@latest askr <command> ...` (Node 22 or newer) and read its JSON output. A command can take up to 2 minutes (the first `npx` install plus up to 85 seconds of work); allow it that long. If a command is killed or ends with no JSON output, run it again once.

Run, in order:

For a new store always pass the source: `--source admin` for products from a file or collected by you, `--source connector --platform <shopify|woocommerce|google>` with `--shop-url` or `--feed-url` for a shop platform. When updating while keeping the current products, leave out --source, --platform, --shop-url and --feed-url too (another --source would remove the store's connector).

Finish with a short summary:

- Admin, the fallback for anything: https://app.askr.elisym.network/admin/
- Plan: the plan name from `askr status` (tier.name) if the store is active. Pricing: https://askr.elisym.network/#pricing
- If I chose a paid plan, the store is pending with "awaitingPlan": false or suspended, or `askr plan` exited with code 5: the store is not live yet. Otherwise message us at https://askr.elisym.network/contact with your Store ID and the plan you chose. Once it is active (for Free later: run `askr plan free` again), run, in order, the exact products, policy and `askr status --probe` commands you would have run (list each one with its file names; tell me where the policy drafts are).
- To update products later: change the file and run `askr products --file <file> --replace` (dry run first); a connector syncs on its own. Policies: `askr policy`.
- What I still have to do (paste the snippet, deploy, add the meta tag, run `askr connector`), if anything.
```

## What the agent asks you

One numbered list, once, each with the agent's proposal, so you can answer "all fine" or correct a few:

- whether to update the store this computer already has, or make a separate one (only if `askr status` found one). For an update it proposes the store's current name, origins, language, currency and policies, and leaves out the flags and policy commands for what you keep;
- the store name, the https addresses your site runs on, the language and the currency;
- where your products come from: your shop (a connector for Shopify, WooCommerce or a Google product feed), a CSV or JSON file you give it, or products it collects from your codebase or product pages;
- your returns, shipping, warranty and FAQ (for Shopify only warranty and FAQ: returns and shipping come from the shop): for each page your site has, what it states, condensed, for you to confirm, correct or replace. Where your site has no such page, the agent proposes nothing and asks you for the terms; a policy you give no terms for, even after "all fine", is not published, and the agent never uses terms that neither your site nor you gave;
- the assistant's name, voice and instructions, and an optional greeting and contact link. When you update an existing store, it proposes keeping the current ones, and leaves out the flags for what you keep;
- where the widget goes;
- the plan, Free or paid, only while the store has none yet. You must choose; there is no default.

After your answer it asks again only before hiding products, or if you did not choose a plan.

## Your secret key

The store's owner key is its identity: it signs your settings and signs you in to the [admin](https://app.askr.elisym.network/admin/). The CLI keeps it on your computer in `~/.elisym/.askr/<profile>.json` (`default.json` unless you use `--profile`), a file only your user can read, outside any project folder. It is never printed, and the prompt tells the agent never to read it. The CLI also never sends it: a `--file`, `--voice-file` or `--instructions-file` inside that folder, or holding an owner key in hex or as an nsec, is refused with `secret_in_file` (exit 2).

Back it up yourself, in your own terminal:

```bash
npx -y @elisym/cli@latest askr export-key --out ~/askr-key.txt
```

It writes the same key file the admin downloads (the secret key, your Store ID and how to sign in), never over an existing file. Save its content in your password manager and delete the file. With it you can always sign in to the admin, which can do everything the CLI does and more.

## Command reference

Every command is run as `npx -y @elisym/cli@latest askr <command> ...` (`-y` so `npx` never stops at its install prompt, `@latest` so a stale cached CLI never runs). Every command takes `--profile <name>`, prints exactly one JSON object on stdout, and never asks anything.

| Command                                              | What it does                                                                                                                                                                                                                                                                                                                          |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `askr init`                                          | Creates the owner key (saved before anything is sent) and the store, signs its settings and the authorization of the server's catalog key, and sets up or removes the connector. A new store ends **pending**; `init` never chooses a plan. Re-running it with the same flags signs nothing new.                                  |
| `askr plan free`                                     | Chooses Free: the store goes live at once and its settings are published.                                                                                                                                                                                                                                                           |
| `askr plan <starter\|growth\|pro\|scale> [--yearly]`  | Prints `checkoutUrl`, a Stripe Checkout link for the human to open and pay (monthly, or yearly with `--yearly`); the command never opens it. The store goes live once the payment goes through: `askr status` then shows it `active`. Enterprise is a message to us with your Store ID.                                           |
| `askr products --file <file>`                        | Publishes products from a `.json` file (an array of products, or `{ "items": [...] }`) or a `.csv` file. `--dry-run` shows what would change (on a pending store it checks the file on your computer and compares product ids with what is listed, publishing nothing). `--replace` treats the file as the whole catalog: listed products missing from it are hidden; when it would hide any, it stops after the dry run (exit 1, `would_hide`) unless `--allow-hide` is given.                       |
| `askr policy --slug <slug> --title <text> --file <md>` | Publishes one policy page (Markdown, up to 16 384 characters). Removing one is done in the admin.                                                                                                                                                                                                                                   |
| `askr connector`                                     | Previews the shop connector, turns it on only if the preview is fine, and waits for its first sync.                                                                                                                                                                                                                                 |
| `askr status [--probe]`                              | The store: status, plan (`tier`), `awaitingPlan`, `billing` (the paid plan, its `status`, `currentPeriodEnd`, `cancelAtPeriodEnd`), name, origins, language, currency, products (`listed`, `visible`), policies, catalog sync, connector, usage. `--probe` also asks for a chat session from your first site, as the widget does; on a pending store it prints `"probe": { "result": "skipped", ... }`, and a failed probe still prints the whole status.                                                                                                                      |
| `askr embed`                                         | The widget snippet, the element form, the verification meta tag, the CSP sources, where to paste on common site builders, the add to cart hook (for products from a file), and the site's `llmsTxt` with its `llmsTxtUrl`. `--llms-txt <path>/llms.txt` writes that file, or appends its Shopping assistant part to an existing `llms.txt`.                                                                                                                                                      |
| `askr export-key --out <path>`                       | Writes the owner key file for your password manager (mode 0600, never overwrites). Run it yourself, never through an agent.                                                                                                                                                                                                         |

`askr init` flags: `--name <text>` and `--origin <https origin>` (repeat it per address; both required for a new store), `--language <bcp47>` and `--currency <ISO 4217>` (default `en` and `USD` for a new store), `--source admin|connector`, `--platform shopify|woocommerce|google`, `--shop-url <url>`, `--feed-url <url>` (Google only), `--display-name`, `--greeting`, `--launcher-text <text>` (the text on the button that opens the chat, up to 24 characters; `""` restores "Ask AI"), `--contact <https url>`, `--voice-file <path>` and `--instructions-file <path>` (the assistant's private voice and instructions, from files), `--owner-key-file <path>` and `--update`. Flags you leave out keep the store's current settings; the `--origin` flags given replace the whole list of sites. On an existing store, a `--source` other than its own removes its connector.

The CSV format is the admin's, read by the same parser: see [Import from a CSV file](/askr/admin#import-from-a-csv-file). A JSON product has `d`, `title` and `price` (`amount` as a string, `currency`), and optionally `summary`, `description`, `images`, `url`, `topics`, `attrs`, `options`, `variants` and `visibility`. `d` must stay stable (the SKU, handle or URL slug); `url` must be on one of the store's sites, or the chat does not show the link.

### Exit codes and resuming

| Code | Meaning                                                                                                                         |
| ---- | ------------------------------------------------------------------------------------------------------------------------------- |
| 0    | Done. `askr products` also exits 0 with `"sync": "running"` when its accepted sync is still running: follow it with `askr status`. |
| 1    | Bad input: a flag, a file, a setting. Fix it and run again.                                                                     |
| 2    | A key problem: no owner key for the profile, an unreadable key file, another key in the profile.                                |
| 3    | Refused: needs a human (the error's hint says what to do).                                                                      |
| 4    | Not done yet: run the `resume` command it prints.                                                                               |
| 5    | A plan or capacity limit, or a store that is not active: the output carries how to upgrade.                                     |
| 6    | The profile's existing store has another name or other origins.                                                                 |

Each command finishes within 85 seconds, so a coding agent's two-minute command limit is never reached; whatever is still running on the server goes on, and `askr status` follows it. An exit 4 always carries `resume`, the exact command that finishes the job (with `--profile` when you used one), and sometimes `retryAfterSeconds`: wait that long (otherwise about a minute) and run it once.

## Several stores, updates, another computer

- **Several stores** on one computer: add `--profile <name>` to every command. Each profile has its own key file and its own store; for a new one the agent first checks with `askr status --profile <name>` that the name is unused (`"store": null`). To have the agent update one of them, name its profile in your request: the agent runs `askr status --profile <name>` before proposing anything and treats that store as the one to update.
- **Updating products later**: change the file and run `askr products --file <file> --replace`, dry run first. A connector syncs on its own. Policies: `askr policy` again with the same slug.
- **Another computer, or a store made in the admin**: run `askr init --owner-key-file <path>` with the key file the admin downloaded (or that `export-key` wrote). The key is read from the file, never from a flag. The file must hold the store's secret key (the nsec): one that only holds its Store ID or public key is refused with `no_store_for_key` (exit 2), and nothing is saved.

## Your Store ID

The summary names your Store ID, and `npx -y @elisym/cli@latest askr status` prints it as `storeId`. See [Find your Store ID](/askr/overview#find-your-store-id) for where else it is, and how to upgrade with it.
